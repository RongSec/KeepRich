## 1. 版本目标与范围界定

### 1.1 一句话目标

**让 v0.4.0 在真机上"能用、不丢数据"：release 扫码恢复可用，用户数据以云端快照为唯一事实源自动持久化（彻底取消"先备份再恢复"流程），沙漏真正流动，邮箱可直接注册，部署切到本账号新云应用。**

### 1.2 本次范围内（In Scope）

| # | 变更 | 归属诉求 |
|---|---|---|
| 1 | Android release 构建（R8）扫码可用 | ① |
| 2 | 数据持久化改为云端快照自动拉取/推送，取消手工备份-恢复依赖 | ② |
| 3 | 覆盖数据的硬性约束（用户数据优先，禁止旧数据回写） | ② |
| 4 | 沙漏重做为"上腔→细颈→下腔堆积→循环"的连续流动 | ③ |
| 5 | 邮箱 + 密码自助注册（无验证码），邮箱即登录账号 | ④ |
| 6 | 部署指向新云应用并发布（App / Web / 后端三端一致） | ⑤ |
| 7 | 扫码失败态文案与错误上报可读化 | ① |

### 1.3 明确不做（Out of Scope）

- **不改账务模型与统计口径**：收入/支出/投资/未来财务等业务算法、字段、报表口径一律不动。
- **不做邮箱验证码、不做邮件服务**（不发验证邮件、不发密码重置邮件）；密码找回仍由管理员重置。
- **不做第三方登录**（微信 / Google / Apple）。
- **不迁移旧云应用数据**：旧应用属其他账号（`wbapp_Wb18t2EDvXDMyVcNeOC4nZ` 无法访问），历史数据如需保留由管理员从本地导出的备份人工导入。
- **不做 iOS 构建**；不改 Web 端路由结构。
- **不换数据库**：仍是沙箱内 SQLite（运行期 `/tmp` 副本）+ 云端 `finance_snapshot` JSONB 快照。
- **沙漏不引入视频/3D 引擎/图片素材**（避免包体与跨端渲染差异），仍用 Flutter 自绘。
- **不做多租户数据隔离改造**：沿用现有 JWT + 家庭（family）模型。

### 1.4 非功能约束

| 项 | 约束 |
|---|---|
| 兼容性 | 接口向后兼容，旧版 App 仍可登录与读写；新增字段/接口不得破坏老客户端 |
| 性能 | App 首页与沙漏背景在中端机 ≥50fps；快照推送不阻塞业务请求（异步） |
| 数据安全 | 云端快照访问凭 `x-wb-webapp-access-key`，禁止把密钥硬编码进 App/Web 前端产物 |
| 可回滚 | 每次快照推送保留最近 5 个历史版本，异常时可回到上一版 |

| R-03 | **云端快照自动推送（写后同步）** | 任一写操作（新增/修改/删除账目、计划、投资、家庭成员等）成功后，异步把全量快照 `POST/PATCH .../finance_snapshot?id=eq.1`（`payload` = 现有 `/api/admin/backup` 同构 JSON，`updated_at` 更新）；防抖 1–2s 合并、失败指数退避重试，且**不影响用户请求返回** | ① App 新增一笔支出，接口 200 返回耗时与改动前无显著差异（≤+150ms）；② 新增后 ≤10s 内云端 `GET` 到 `payload` 含该笔记录、`updated_at` 更新；③ 断网状态下新增数据仍成功（本地可写），恢复网络 ≤30s 内自动补推成功；④ 连续 100 次写操作不产生 100 次推送（合并生效，推送次数明显少于写次数） |

| R-05 | **邮箱 + 密码注册（无验证码）** | 新增 `POST /api/auth/register`：入参 `email`、`password`、`nickname?`；邮箱去空格转小写后作为唯一登录标识写入 `username` 与 `email` 两字段（保持登录接口不变）；密码沿用现有强度规则 | ① 新邮箱 + 合规密码 → 200，返回 token 并可直接进入概览页（无需再登录一次）；② 同一邮箱再次注册 → 409，文案「该邮箱已注册」；③ 密码 <8 位或缺字母/数字 → 400 且返回中文提示；④ 邮箱格式非法 → 400（后端校验，前端同步拦截）；⑤ 注册成功后可立即调用 `/api/auth/me`、`/api/overview` 正常返回 |
| R-06 | **登录兼容邮箱与老用户名** | `POST /api/auth/login` 的 `username` 字段同时匹配 `users.username` 或 `users.email`；老账号（非邮箱用户名）继续可登录 | ① 用邮箱登录成功；② 用 v0.3.1 已有用户名账号登录成功；③ 邮箱大小写混输（如 `A@B.com`）可登录成功；④ MFA 账号流程不变（开启 MFA 时仍要求验证码） |

### 4.3 扫码页失败态（改动）

三段式布局（纵向居中）：

1. 图标：相机禁用 / 权限 / 初始化异常三种区分；
2. 中文原因（不出现 exception 类名与堆栈）：
   - 权限拒绝：「相机权限未开启。请在系统设置中允许"永远富裕"使用相机。」
   - 不支持：「当前设备不支持相机扫码，请手动输入服务端地址。」
   - 相机被占用：「相机被其他应用占用，请关闭后重试。」
   - 其他：「相机启动失败，请重试或手动输入服务端地址。」
3. 按钮：「重试 / 重新申请权限」（主）+「手动输入服务端地址」（次）。

- 失败时隐藏取景框装饰层（避免压住文案）；保留 AppBar 手电筒开关（不支持时 toast 提示）。

### 4.4 沙漏视觉规范（重做）

| 部件 | 视觉要求 |
|---|---|
| 外形 | 上下两个玻璃腔（圆角/弧底）+ 中间细颈，金边勾勒，玻璃有轻微高光与内反光；整体居中，可嵌入现有金沙/金币主题 |
| 上腔 | 沙面为一条随重力变化的曲面；随时间**持续下降**；表面有细碎高光与颗粒纹理 |
| 细颈 | 宽度约 2–4px 的**连续沙束**：颗粒从颈口成束下落，粒径略小、速度更快，中段有加速（重力），可见少量散落颗粒 |
| 下腔 | 落下的沙在底部堆成**锥形沙丘**，顶点位于细颈正下方，堆高随时间**单调上升**，坡面有滑落/堆积的细颗粒活动 |
| 循环 | 上腔见底后整轮重置（整体翻转 180° 动画，或短暂过渡后重新灌满），无限循环；**不得**停在静止画面 |
| 守恒 | 上腔减少量 = 下腔增加量（视觉总量恒定，不"流干"、不溢出） |
| 交互 | 不依赖传感器：静置也必须流动；倾斜时流向/沙面倾角响应，但不中断流动 |
| 性能 | 用自绘 Canvas + 预渲染 sprite，避免逐帧创建对象；Web 与 Android 表现一致 |

> 实现载体（复用 `gold_sand.dart` 改造 或 新建独立 widget）由架构师决定，PRD 只约束上述视觉与性能验收。

## 5. 数据行为约定（红线）

### 5.1 唯一事实源

- **云端 `finance_snapshot`（单行 `id=1`，`payload` = 全量 JSONB，`updated_at` = 最后写入时间）是唯一事实源**；SQLite 是运行期缓存副本（沙箱重启会丢，属预期）。
- 快照结构与现有 `GET /api/admin/backup` 导出同构（复用同一序列化/反序列化代码，避免两套格式漂移）。

### 5.2 允许覆盖的数据场景（白名单）

| 场景 | 条件 |
|---|---|
| 管理员手动导入备份 | 备份 `updated_at` **≥** 当前云端快照 `updated_at`；或管理员在确认框中显式勾选「强制覆盖」 |
| 首次部署/空库启动 | 云端有快照、本地为空 → 允许云端覆盖本地 |
| 历史版本回滚（P2/R-12） | 管理员在管理端选择版本 + 二次确认 |

### 5.3 绝对不允许（红线）

1. **任何自动流程**（服务启动、部署脚本、sync.sh、发布流水线）**不得**在没有 `updated_at` 比较的情况下用旧备份/旧快照覆盖用户数据。
2. **发布流程不得再把"先导出备份 → 发布 → 再恢复备份"作为默认步骤**；发布后靠自动拉取快照恢复，而不是靠人工 restore。
3. **云端快照为空/不可读时，不得反向清空本地库**（拉取失败 = 什么都不做，只告警）。
4. 用户在一次会话内的写入，不得被同会话内的后台同步循环用更旧的副本覆盖（推送前必须读取最新本地状态）。
5. 快照密钥只允许存在于后端配置/环境变量，禁止进 App、Web 前端产物与公开仓库。

### 5.4 冲突处理规则

| 情况 | 处理 |
|---|---|
| 本地有数据、云端 updated_at 更新 | 云端覆盖本地（记录日志 + 同步状态可见） |
| 本地有数据、云端 updated_at 更旧 | 以本地为准并**推送**覆盖云端（不反向覆盖用户） |
| 云端为空、本地有数据 | 启动后立即把本地推送上去 |
| 推送失败 | 指数退避重试（1s/2s/4s…封顶 60s），不清空任何数据；连续 3 次失败在 App 顶部提示 |
| 同一主键冲突（导入时） | 沿用现有"查-插"逻辑（按主键先删/后插），但必须先过 5.2 的时间戳闸门 |

## 6. 待确认问题（不阻塞开发）

| # | 问题 | 建议默认方案 |
|---|---|---|
| Q1 | 老用户名账号（非邮箱）是否继续保留登录？ | 保留，login 同时匹配 `username` 或 `email`（R-06） |
| Q2 | 注册后是否需要邀请码/家庭绑定？ | 本版不做，注册即独立用户，后续可加入家庭 |
| Q3 | 是否需要"忘记密码"自助重置？ | 本版不做（需邮件服务）；仍由管理员重置 |
| Q4 | 云端快照用单行全量还是分表存储？ | 单行全量（当前数据量小，实现最简）；如数据量增长再分表 |
| Q5 | 沙漏是复用 `gold_sand.dart` 改造还是新建 widget？ | 由架构师决定，满足 4.4 与 R-08 验收即可 |
| Q6 | 旧云应用里的历史数据是否需要人工迁移？ | 默认不迁移；如需要，管理员用本地备份在导入闸门下 `force` 导入一次 |
